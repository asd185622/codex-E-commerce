# E-Commerce 前端設計與實作規格

> 狀態：第一版討論結論
> 用途：作為後續 Codex 對話與前端實作的共同依據
> 專案定位：以 Spring Boot 後端能力為主的求職作品集
> 實作進度：請參考 [`development-status.md`](./development-status.md)

## 1. 專案目標

為現有 `springboot-mall/` 建立一套簡單、明確且容易閱讀程式碼的電商前端。

前端的主要任務是：

- 展示現有商品、會員與訂單 API。
- 提供完整但不過度擴張的購物流程。
- 提供獨立商品管理介面，以涵蓋商品新增、修改與刪除 API。
- 保持適合作品集的視覺完成度，但不讓前端複雜度蓋過後端重點。
- 讓前端初學者能理解專案結構與主要程式碼。

## 2. 已確認的技術選擇

- React
- JavaScript，不使用 TypeScript
- Vite
- React Router
- Axios
- React Context
- 一般 CSS
- `localStorage`

本專案不使用：

- Redux
- Tailwind CSS
- 大型 UI 元件庫
- JWT 與管理員角色驗證（RBAC）；商品管理固定維持明確標示的 Demo

### 開發環境

- 前端建立於 `frontend/`。
- Spring Boot 後端維持於 `springboot-mall/`。
- 後端預設位址為 `http://localhost:8080`。
- 開發期間使用 Vite proxy 轉送 API，避免在元件內寫死後端網址並減少 CORS 問題。
- Axios 實例集中管理 base URL、逾時與共用錯誤處理。

## 3. 產品與視覺方向

### 品牌定位

- 暫定名稱：**拾物 SHIWU**。
- 定位：生活選物商城。
- 目標使用者：希望快速瀏覽、搜尋並購買不同類型商品的一般消費者。
- 首頁的單一任務：讓使用者快速理解商品分類，並開始瀏覽商品。

後端分類在前端使用較自然的中文名稱：

| 後端值 | 前端名稱 |
|---|---|
| `FOOD` | 食味 |
| `CAR` | 行旅 |
| `E_BOOK` | 閱讀 |

此映射僅屬於前端顯示，不修改後端 `ProductCategory`。

### 設計語氣

- 明亮、理性、簡潔。
- 以清楚的資訊層級和留白為主，不加入大量裝飾或動畫。
- 不採用常見的米色精品選物風，也不使用漸層作為主要視覺。
- 所有使用者介面文字以繁體中文呈現。

### 色彩

| 用途 | 色彩 |
|---|---|
| 頁面背景 | 冷白 `#F6F8FC` |
| 主要文字 | 墨藍 `#172033` |
| 主要操作與品牌識別 | 識別藍 `#3157D5` |
| 少量提醒與購物提示 | 珊瑚橘 `#F26B4A` |

珊瑚橘只用於購物提示、庫存提醒或需要注意的狀態，不作大面積背景。

### 字體

- 中文使用清楚、易讀的無襯線字體。
- 英文品牌、價格與小標可使用較窄的幾何無襯線字體。
- 字體載入失敗時必須有可靠的系統字體 fallback。

### 設計記憶點

分類入口以「**味／行／讀**」三個大字呈現，作為網站唯一主要視覺記憶點。其他區域維持安靜、規律與易讀，避免同時加入多個搶眼效果。

### 動效

- 僅使用必要的按鈕、商品卡與表單狀態轉場。
- 不使用大幅度視差、背景粒子或大量滾動動畫。
- 支援 `prefers-reduced-motion`。

## 4. 資訊架構與頁面

| 路由 | 頁面 | 主要功能 |
|---|---|---|
| `/` | 首頁 | 品牌介紹、分類入口、本週選物、最新商品 |
| `/products` | 商品列表 | 搜尋、類別篩選、排序、分頁 |
| `/products/:id` | 商品詳情 | 商品資料、庫存、數量、加入購物車 |
| `/cart` | 購物車 | 調整數量、移除商品、金額摘要、建立訂單 |
| `/login` | 登入 | 呼叫 Spring Security 登入端點並建立後端 session |
| `/register` | 註冊 | 建立會員帳號 |
| `/orders` | 我的訂單 | 依登入回傳的 `userId` 查詢訂單及分頁 |
| `/admin/products` | 商品管理 | 商品列表、搜尋、篩選、排序、分頁、刪除 |
| `/admin/products/new` | 新增商品 | 新增商品表單 |
| `/admin/products/:id/edit` | 修改商品 | 載入既有資料並更新商品 |

### 首頁結構

```text
┌ 品牌 ─ 商品分類 ─ 搜尋 ─ 登入 / 購物袋 ┐
│ 本週選物文案        │ 主打商品圖片       │
├ 味 ───────── 行 ───────── 讀 ─────────┤
│ 最新商品 / 商品卡片網格                 │
│ 商品圖・名稱・分類・價格・庫存狀態       │
└ 專案與 GitHub 入口 / 管理 Demo 入口      ┘
```

首頁第一屏直接呈現真實商品與分類，不使用只有口號、缺乏內容的大型 Hero。

### 商品管理介面

- 與消費者前台分離。
- 使用資訊密度較高的表格、狀態標籤和清楚的表單。
- 沿用前台色彩、字體與間距規則。
- 管理入口放在頁尾並標示「管理 Demo」，不占用主要購物導覽。
- 刪除前必須顯示包含商品名稱的確認對話框。
- 新增與修改共用相同欄位與驗證規則。

## 5. 現有 API 對應

### 商品

| 方法與路徑 | 前端用途 |
|---|---|
| `GET /products` | 首頁商品、商品列表、管理列表 |
| `GET /products/{productId}` | 商品詳情、編輯商品資料 |
| `POST /products` | 新增商品 |
| `PUT /products/{productId}` | 修改商品 |
| `DELETE /products/{productId}` | 刪除商品 |

`GET /products` 使用：

- `category`：`FOOD`、`CAR`、`E_BOOK`
- `search`：商品名稱關鍵字
- `orderBy`：前端只提供 `created_date` 或 `price`
- `sort`：前端只提供 `asc` 或 `desc`
- `limit`
- `offset`

商品表單欄位：

- `productName`
- `category`
- `imageUrl`
- `price`，不得小於 0
- `stock`，不得小於 0
- `description`，選填

### 會員

| 方法與路徑 | 前端用途 |
|---|---|
| `POST /users/register` | 註冊 |
| `POST /users/login` | 登入 |

登入與註冊欄位皆為：

- `email`
- `password`

### 訂單

| 方法與路徑 | 前端用途 |
|---|---|
| `POST /users/{userId}/orders` | 建立訂單 |
| `GET /users/{userId}/orders` | 查詢使用者訂單 |

建立訂單時，購物車轉換為：

```json
{
  "buyItemList": [
    {
      "productId": 1,
      "quantity": 2
    }
  ]
}
```

訂單列表支援 `limit` 與 `offset` 分頁。

## 6. 前端程式結構原則

建議以功能責任分層：

```text
frontend/src/
├── api/          # Axios 實例與商品、會員、訂單 API
├── components/   # 可重用的小型 UI 元件
├── context/      # 使用者與購物車狀態
├── layouts/      # 前台與管理介面的共用版面
├── pages/        # 路由頁面
├── styles/       # 色彩、字體、間距與共用樣式
└── utils/        # 金額、日期與錯誤訊息轉換
```

實作規則：

- 頁面負責組合功能，API 呼叫集中在 `api/`。
- 不在多個元件內重複 Axios 設定或後端網址。
- 元件保持單一責任，避免過早抽象化。
- React Context 只管理登入使用者與購物車，不將所有伺服器資料放入全域狀態。
- 購物車保存至 `localStorage`；會員狀態以後端 session 為準，啟動時呼叫 `/users/me` 還原。
- 價格以新台幣整數格式顯示。
- API 錯誤轉換成使用者能理解的繁體中文訊息。

## 7. 必要使用狀態

所有資料頁面必須處理：

- 載入中
- 無資料
- API 失敗
- 找不到商品
- 圖片載入失敗
- 商品售罄

所有表單必須處理：

- 必填欄位
- Email 格式
- 價格與庫存不可為負數
- 購買數量至少為 1，且不得超過庫存
- 送出中禁止重複提交
- 成功與失敗回饋

購物車建立訂單前：

- 未登入時引導至登入頁。
- 商品售罄或數量超過庫存時禁止送出。
- 訂單成功後清空購物車並顯示訂單結果。

## 8. 圖片政策

實作商品內容時再進行圖片搜尋與選擇，不直接使用來源不明的圖片。

現有商品圖片的逐筆來源、授權風險與替換順序記錄在 [`product-image-licenses.md`](./product-image-licenses.md)。作品頁或作者無法確認的圖片一律視為尚未完成授權查核。

- 優先使用公有領域、開放授權，或明確允許免費商用的圖片。
- 使用前重新確認圖片網站的最新授權條款。
- 記錄圖片來源、作者（若授權要求）與授權頁面。
- 選擇構圖、比例與色調一致的圖片。
- 優先保存可合法隨專案使用的本機副本，避免外部連結失效。
- 不將搜尋結果縮圖網址直接當作正式商品圖片。
- 為所有商品圖片提供有意義的替代文字。

## 9. 已知限制與非本階段範圍

### 驗證與權限

會員登入改由 Spring Security 管理伺服器端 session，密碼以 BCrypt 雜湊保存，前端透過 `/users/me` 取得目前會員，所有非 GET 請求需攜帶 CSRF token。

因此：

- `/users/{userId}/orders` 必須與目前 session 會員相同，避免跨會員存取。
- `/admin/products` 固定為 Demo 管理介面，不加入角色與商品寫入權限驗證。
- 前端路由保護只改善操作流程，真正的權限判斷必須留在後端。
- README 與管理頁需清楚揭露本專案不實作 RBAC。

本專案不新增 JWT、角色欄位或 RBAC；既有 MD5 會員資料需清除後重新註冊，不提供舊密碼相容層。

### 其他非本階段功能

- 真實金流
- 配送與地址
- 優惠券
- 收藏與評論
- 第三方登入
- 圖片上傳服務；商品管理先使用 `imageUrl`
- 後端架構重整

## 10. 響應式與可用性

- 支援桌面、平板與手機。
- 手機版保留搜尋、分類、加入購物車與結帳等核心操作。
- 可互動元件具備清楚的鍵盤焦點。
- 圖示按鈕需有文字標籤或 `aria-label`。
- 文字與背景維持足夠對比。
- 表單錯誤需與對應欄位建立關聯。
- 管理表格在小螢幕可改為卡片式資料列或水平捲動，不壓縮到無法閱讀。

## 11. 建議實作順序

1. 建立 Vite 專案、路由、Axios、共用版面與設計變數。
2. 完成首頁、商品列表與商品詳情。
3. 完成登入、註冊與展示型使用者狀態。
4. 完成購物車、建立訂單與訂單列表。
5. 完成商品新增、修改與刪除管理頁。
6. 搜尋並整理合法可用的商品圖片。
7. 補齊手機版、錯誤狀態、空狀態與無障礙細節。
8. 驗證所有現有 API 都能由前端操作。

## 12. 完成標準

- 現有商品、會員與訂單 API 皆有對應前端操作。
- 消費者流程和管理 Demo 清楚分離。
- 使用者可以搜尋、篩選、排序與分頁瀏覽商品。
- 使用者可以註冊、登入、管理購物車、建立訂單並查看訂單。
- 商品可以由管理 Demo 新增、修改與刪除。
- 頁面在桌面與手機皆可正常使用。
- 所有資料頁面具有載入、空資料與錯誤狀態。
- 圖片具有可追溯授權來源與替代文字。
- 前端程式碼維持適合 JavaScript／React 初學者閱讀的結構。
- `springboot-mall/` 的既有 Controller–Service–DAO 架構不因前端實作而重組。
